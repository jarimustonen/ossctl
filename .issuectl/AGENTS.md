# Agents policy (`.issuectl/AGENTS.md`)

What an agent should know before it touches this repository's issue tracker.
The generated block at the bottom is the schema and transition reference,
regenerated by `issuectl doctor --fix` from `issues/.schema.yaml` and
`.issuectl/transitions.yaml`; the prose above it is hand-written and survives
regeneration. Project-wide guidance, including the release policy and the
standard for what earns a place in the tracker, is in the top-level
`AGENTS.md`; this file only covers the tracker itself.

## What the tracker is for here

Issues are the one place where design happens. A feature is opened as an issue
before it is built, and any planning document lives under the issue that needs
it rather than in `TODO.md` or a loose file, so that the reasoning stays next to
the decision it produced. Scheduling is also frontmatter: `lane`, `lane_seq`,
`blocked_by` and `collision` are what `issuectl dag` reads, and stint
orchestration starts from that view rather than from any prose backlog.
`TODO.md` carries only the handoff narrative.

Admission is deliberately strict. The standard in the top-level `AGENTS.md`
asks for a failure that can actually occur in this project, on this path, with
damage beyond an error message. The reason is that every tracked item costs the
maintainer's attention at triage, and the tracker has already carried a wave of
plausible-sounding review findings that no observed failure ever backed. When a
finding does not meet the bar, the useful act is to say so where it was raised,
not to file it and let it be closed later.

## Writing through issuectl

Frontmatter is written with `issuectl` (`set`, `update`, `close`, `note`,
`check`, `apply`), not by editing `item.md` by hand. The tool holds the repo
write lock, validates against the schema, bumps `updated:` and keeps the key
order that `fmt` and the merge driver expect. This matters here because several
agents often work in parallel worktrees: a hand edit passes silently at the
time and surfaces later as a broken `dag` view, a query that no longer matches,
or a merge conflict in a file that was meant to union-merge. Body text below the
frontmatter is ordinary markdown and can be edited directly, though `note`,
`check` and `close --comment` produce the timestamped, attributed blocks that
the rest of the tooling recognises.

The command surface is documented by the binary: `issuectl <command> --help` is
the authority on flags and behaviour, and `issuectl --json` is the form agents
consume. The `/issue` skill describes the workflows, but it was installed for an
older issuectl than the one on this machine and lags in places (it still
describes a `closed/` directory move that the flat layout no longer performs),
so when the two disagree, trust the binary. Write as yourself: `note --as` and
`close --as` record who made the call, and closures in this repository name the
agent or stint that made them.

## Closing an issue

A closure is a durable maintainer decision, so it records the reason and a
reopen condition in the issue itself. `close --comment` writes that rationale
under `## Resolution` in one step; `--status` picks the closing status when the
default (`fixed` for bugs, `done` otherwise) is wrong, and the `wontfix`,
`duplicate` and `obsolete` closures here each say why and what would reopen
them. Recording the landing commit (`--commit` or a `Fixes-Issue: @<slug>`
trailer, `Refs-Issue: @<slug>` for related work) is what lets `issuectl
changelog` and `sync-commits` connect history to the tracker afterwards.

Reports filed by agents rather than by the maintainer go through
`issuectl intake file`, which lands them as `untriaged`; accepting, deferring
or rejecting them is the maintainer's surface, not the reporter's.

## Health

`issuectl doctor` reads the whole tracker and reports dangling references,
schema violations and legacy layouts. Running it before committing issue
changes is cheap and catches the hand-edit and merge accidents described above;
`--fix` also regenerates the block below, so a "schema-derived block is out of
date" finding is resolved that way rather than by editing between the
sentinels.
