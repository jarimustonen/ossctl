# v0.11.0 three-platform recovery

This is the one-time conductor procedure for the partially released Shipshape v0.11.0.
It is executable in [`scripts/recover-v0.11.0-three-platform.sh`](../../scripts/recover-v0.11.0-three-platform.sh).

- `shipshape-core` and `shipshape-cli` 0.11.0 are already on crates.io.
- Cancelled cargo-dist workflow `32652510525` successfully built and attested:
  - artifact `9496586399`: `shipshape-aarch64-apple-darwin.tar.xz`, SHA-256
    `15c35f00196da6da1d5d852b99dd5de51d8f1895aa97207690814b581273c988`;

  - artifact `9496596260`: `shipshape-x86_64-unknown-linux-musl.tar.xz`, SHA-256
    `83313adf0e1bc91cffb78fea7146f3ecc8280a58b57180c5a0d1cbb3989d9d86`.
- The GitHub Release is absent. The tap may contain ADR-0005's authorized marker-only
  `Formula/shipshape.rb` bootstrap, but no installable formula.
- Engine run `01M0QQMW8Y6SWRR2G383M0KVJX` was sealed with four platforms. Its

Do not rerun workflow `32652510525`: its workflow came from the immutable tag and still
contains the withdrawn Intel job. Do not resume the engine run with a changed contract.
A resume would pretend that a four-platform sealed plan completed under a three-platform
policy.

## Why the run is abandoned first

The script explicitly abandons `01M0QQMW8Y6SWRR2G383M0KVJX` **after all read-only
preflight and local artifact validation, but before creating the Release or pushing the
formula**. That is the last safe point: preflight failures leave the run resumable for
forensics; once the manual fallback mutates a channel, the old plan must already be
terminal and must never compete with the conductor. The manual fallback does not and
must not rewrite its journal to green.

## Procedure

From merged, pushed, CI-green `main`, with a clean tree and authenticated `gh`:

```sh
# Read-only/local rehearsal. This downloads the three pinned Actions artifacts,
# checks their fixed hashes and GitHub attestations, generates cargo-dist's global
# installer/checksum/source artifacts from the immutable tag, removes only the
# withdrawn Intel entry from dist-manifest.json, and renders the exact formula.
scripts/recover-v0.11.0-three-platform.sh --prepare-only

# External conductor execution. The environment value is a deliberate typo guard.
SHIPSHAPE_V0110_RECOVER=execute \
  scripts/recover-v0.11.0-three-platform.sh --execute
```

The execute mode performs this order:

1. Re-check clean state, local and remote tag identity, cancelled workflow identity, and
   both crates.io versions.
2. Download only artifact IDs `9496586399`, `9496606237`, and `9496596260`; verify the
   fixed checksums, sidecars, and GitHub attestations.
3. Use pinned cargo-dist 0.28.2 with merged main's three-target config to generate
   `shipshape-installer.sh`; derive the source archive directly with `git archive` from the
   pinned tag and rebuild its sidecar plus `sha256.sum` from fixed hashes. Preserve
   cargo-dist's complete manifest schema while removing only the never-built Intel records
   and replacing the stale four-platform announcement.
4. Inspect any existing Release and tap formula read-only, accepting only matching
   metadata/assets (including a safe partial upload) and either a byte-identical formula or
   ADR-0005's exact marker-only bootstrap; require
   canonical CI-green main. Then abandon old run `01M0QQMW8Y6SWRR2G383M0KVJX` with the
   superseded-plan reason. An already-abandoned run is an idempotent success.
5. Create or complete the GitHub Release at the **existing** verified tag and upload the three
   archives, sidecars, global files, and corrected `dist-manifest.json`. No tag is created,
   moved, or replaced.
6. Write the engine marker formula with the three fixed real checksums by an ordinary
   push to `jarimustonen/homebrew-shipshape`. An existing non-identical formula is a hard
   stop.
7. Download and byte-compare every Release asset, read and byte-compare the formula, and
   re-observe both crates.io packages. The manifest, installer, and formula are checked
   not to claim Intel macOS.

The script is retry-safe at the two external writes: an existing Release may contain a
matching subset that the script completes without clobbering, while any extra or differing
asset is refused; an existing formula is accepted only when byte-identical. Any conflict
stops. It never deletes, overwrites, force-pushes, moves the tag, or invents a checksum.

v0.10.x releases and journals continue to describe the support they actually shipped;
do not edit those records to match the new policy.
