# gh-releases/cargo-dist: no real multi-platform release workflow

## Description

Found during ossctl's OWN 0.1.0 self-cut (stint #9). cargo-dist config is minimal ([package.metadata.dist] dist = true) with no installers/tap/CI release workflow. The self-cut's GitHub Release + binary asset were built and uploaded BY HAND for a single platform (aarch64-apple-darwin) via 'gh release create'. For a proper release, wire cargo-dist (or a release.yml GitHub Actions workflow) to build cross-platform binaries on tag push and attach them, and optionally generate/push the Homebrew formula (which would also address homebrew-adapter-first-formula for the cargo-dist path). Not blocking — the release exists — but the binary matrix is currently macOS-arm64 only.

## Outcome (fixed)

Wired the tag-triggered release pipeline via cargo-dist (dist 0.28.2), config-only — no Rust touched.

- `.github/workflows/release.yml` — GENERATED (`dist generate`) from `dist-workspace.toml`. On a version-tag push it builds the 5-target binary matrix and, via `dist host` → `gh release create`, attaches per-platform archives, shell/powershell installers, and SHA-256 checksums to the GitHub Release. Never runs on branch pushes/PRs (`pr-run-mode = "skip"`). Do NOT hand-edit — regenerate from config.
- `dist-workspace.toml` — the source-of-truth `[dist]` config. Binary matrix: macOS arm64+x86_64, **Linux arm64+x86_64 (musl, static)**, Windows x86_64. Installers: shell + powershell. Build-provenance attestations on (`github-attestations = true`). Homebrew auto-publish deliberately left OFF (owned by `homebrew-adapter-first-formula`).

Verified: `dist plan` lists all 5 targets + installers + checksums, only the `ossctl` binary is distributable; `actionlint` clean (bar cargo-dist's own benign SC2086/SC2129 style notes in autogenerated shell); `cargo fmt --all --check` passes; YAML valid.

Reviewed with `/llm-review` (gemini/openai/anthropic/deepseek). Applied confirmed config-expressible findings: gnu→musl Linux targets (portability), attestations on, corrected an overstated tag-trigger comment (the generated glob matches more than `vX.Y.Z`; glob filtering is not an authz boundary — use a tag-protection ruleset). Rejected deepseek's "gh release create conflicts with dist host" as a hallucination (it is cargo-dist's standard working flow).

Deferred as spin-off proposals (out of scope — inherent to cargo-dist autogen, or would touch `ci.yml`): reproducible-release toolchain pinning (needs a repo-wide `rust-toolchain.toml`; the `rust-toolchain-version` key is deprecated), a generated-workflow drift check in CI, per-job permission scoping / action SHA-pinning / release-concurrency guard / job timeouts (all cargo-dist-owned), and a Windows CI test job.
